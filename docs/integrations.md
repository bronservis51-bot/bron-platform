# Интеграции

Статус на 12.10.2026: **все подключения прототипа работают в demo-режиме** (COST-08). Реальные возможности внешних систем перечислены как «что проверить до реализации»; без аккаунта, тарифа и тестового доступа реальный адаптер не начинается (раздел 1.2).

## 1 Общий контракт адаптера (INT-01…05)

```
команда бизнес-модуля ──(транзакция)──► outbox(topic, payload, dedupe_key)
                                         │
                       process_outbox ◄──┘ (pg_cron каждые 5 мин или «Обработать очередь сейчас»)
                         │  1. сверка: есть ли уже внешний документ с нашим кодом?
                         │  2. если нет — создать
                         ▼
                 результат: done | failed (повтор с задержкой и джиттером) | unknown (сверка) | dead (задача оператору)
                         │
                         ▼
          контракт модуля-владельца: order_transfer_result / article_export_result → деловой статус для пользователя

внешнее событие ──► inbox(source, event_id UNIQUE) ──► process_inbox ──► контракт модуля (order_apply_warehouse_event, opening_create_internal)
                     повтор события = duplicate, не обрабатывается
```

| Требование | Реализация |
| --- | --- |
| Идемпотентность исходящих | `outbox.dedupe_key` уникален; внешний документ получает наш идентификатор (externalCode); перед повтором — сверка по нему |
| Неизвестный результат | Статус `unknown` → следующая обработка сначала ищет документ; дубль не создаётся (AT-05, тест) |
| Повторы | 30 с × 2^попытки + джиттер, максимум 5; затем `dead` и критическая задача очереди снабжения (AT-12, тест) |
| Входящие | Уникальность `(source, event_id)`; обработка асинхронна; ошибка — статус `failed` с текстом |
| Наблюдаемость | Экран «Настройки → Интеграции»: подключения, последняя удача, очередь outbox с бизнес-объектом и причиной, inbox, запуски |
| Восстановление | «Повторить» / «Сверить» / «Решено вручную» (с причиной в аудите) |
| Секреты | В прототипе секретов интеграций нет; в production — только на сервере (Edge Function secrets / secret manager), интерфейс показывает состояние без токена (INT-02) |
| Отключение | `mode = disabled` → команды остаются в очереди, пользователь видит «ожидает передачи» |

## 2 Подключения

### «МойСклад» — demo-адаптер
- **Сейчас:** `warehouse.create_order`, `warehouse.cancel_order`; события `order.accepted`, `shipment.created`, `shipment.delayed`, `shipment.delivered` (кнопки «События склада (демо)» в карточке заказа). Режимы: успех, ошибка, потерянный ответ.
- **Маппинг (план):** заказ партнёра → «Заказ покупателя» (`entity/customerorder`), заявка точки → «Внутренний заказ»/перемещение (A-10, Q-05); строки → позиции с `assortment` по `integration_mapping(catalog_item)`; наш `sales_order.id` → `externalCode`.
- **Проверить до реализации [S6]:** тариф и доступ к JSON API 1.2 и вебхукам; единицы и упаковки; модель цен (типы цен для партнёров); резервирование; статусы заказа; лимиты запросов конкретного аккаунта (в спецификации не фиксируются); есть ли тестовый аккаунт.
- **Реализация (этап 3):** Edge Function `moysklad-adapter` (токен в secrets), вызывается обработчиком outbox через pg_net или worker; входящие вебхуки → Edge Function проверяет источник → `inbox`; периодическая сверка статусов и остатков (INT-05).

### Google Drive — demo-адаптер
- **Сейчас:** `drive.export_article` (корпоративная копия опубликованной редакции), имитация изменения исходника и отзыва доступа (кнопки в статье режима `drive_document`).
- **Проверить [S1, S2]:** тип аккаунта (Workspace/личный), Shared Drive и параметр `supportsAllDrives`, scopes (минимум `drive.file` для экспорта; чтение исходников — `drive.readonly` в ограниченной папке), сервисный аккаунт или корпоративный OAuth, формат экспорта Google Docs (`files.export` → text/markdown или html).
- **Реализация (этап 2–3):** очередь синхронизации; `changes.list` с устойчивым `pageToken`; watch-каналы с продлением до истечения; push — только сигнал перечитать; периодическая сверка; конфликт — кандидатная редакция, а не перезапись (KB-14…16).

### CRM (Bitrix24?) — demo-адаптер
- **Сейчас:** событие «сделка выиграна» → проект открытия; повтор события с тем же ID сделки возвращает существующий проект (OPEN-01, тест).
- **Проверить:** какая CRM действует (Q-09), этап сделки-триггер, вебхуки/REST, права, дубли сделок.

### Банк / финансовая система — не подключено
- **Сейчас:** финансы регистрируют зачисление по выписке вручную (`payment_register`), подтверждает другой сотрудник; одна банковская операция регистрируется один раз (уникальный `bank_ref`).
- **Проверить:** источник выписки (банк-клиент, 1С, Финтабло/Дзен-мани), формат импорта, внешние ID операций.

### Каналы связи (WhatsApp/Instagram/Telegram) — не подключено
- По INT-06: без официального доступа обращения создаются в PWA; неофициальная автоматизация не используется.

### Перевод / AI — не подключено
- Демо-переводы — заранее подготовленные тексты с пометкой. Машинный перевод и AI-поиск — отдельные адаптеры следующего этапа (KB-18) после выбора провайдера и политики данных.

## 3 Порядок подключения после прототипа

1. «МойСклад»: каталог и остатки → PWA (проекция), затем заказ → склад, затем события отгрузки.
2. Google Drive: экспорт копий опубликованных статей, затем исходники `drive_document`.
3. Банковская выписка: импорт для сверки оплат.
4. CRM: событие сделки → проект открытия.
5. Почта / Web Push: только после выбора сервера отправки (iOS — только для установленного PWA [S3]).
