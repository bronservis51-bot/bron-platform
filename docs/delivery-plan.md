# План поставки

## 1 Бюджет прототипа (COST-01…03, COST-12)

| Статья | Решение | Расход |
| --- | --- | --- |
| Хостинг интерфейса | GitHub Pages из публичного репозитория | 0 ₽ |
| База данных, Auth, файлы | Supabase Free: 500 МБ БД, 1 ГБ файлов, без карты | 0 ₽ |
| Домен | Не нужен: адрес `*.github.io` | 0 ₽ |
| Фоновые задания | pg_cron внутри Supabase или ручной запуск | 0 ₽ |
| Почта / SMS | Не используются; пользователи создаются скриптом администратора | 0 ₽ |
| AI / перевод | Не используются; демо-переводы — подготовленные тексты | 0 ₽ |
| Интеграции | Demo-адаптеры; реальные API не подключаются | 0 ₽ |
| Библиотеки | MIT / Apache-2.0 / ISC / MPL-2.0 | 0 ₽ |
| Инструменты разработки | Node.js, git, PGlite на имеющемся компьютере | 0 ₽ |
| CI | GitHub Actions (бесплатные минуты публичных репозиториев) | 0 ₽ |
| **Итого** | | **0 ₽** |

Работа людей, интернет и электричество не учитываются как бесплатные ресурсы — бюджет означает отсутствие новых покупок и счетов (COST-02).

## 5 Миграция данных (MIG-01…04)

1. Инвентаризация: таблицы менеджера, договоры, контакты, файлы Drive, остатки, задолженность, открытые обращения (владельцы процессов подтверждают).
2. Staging-импорт: исходные ID в `integration_mapping`, нормализация точек и партнёров, проверка дублей, единиц, валют и дат; протокол ошибок (механизм — как `report_import`).
3. Финансы: входящее сальдо на дату среза — одна дебетовая/кредитовая корректировка на договор с основанием; старые начисления не пересчитываются.
4. Delta-import изменений после среза; затем явное переключение источника ввода, чтобы не осталось двойного учёта.
