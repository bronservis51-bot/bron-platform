# Дизайн-система

Реализация: [`src/ui/styles.css`](../src/ui/styles.css) (токены и компоненты), [`src/ui/index.tsx`](../src/ui/index.tsx) (React-компоненты), [`src/ui/status.ts`](../src/ui/status.ts) (деловые названия статусов).

## 1 Принципы (UX-01…08)

| Принцип | Как реализовано |
| --- | --- |
| Первый экран отвечает «что сделать, до какого срока, для какой точки, что мешает» | Экран «Сегодня» собирается одной командой `today()` по ролям и области; каждый элемент — ссылка на объект; причина блокировки показывается рядом с задачей |
| Не один дашборд на всех | Блоки «Сегодня» и пункты меню зависят от разрешений; финансист видит согласования, сотрудник точки — ознакомления и обращения |
| Статус — текстом, цвет не единственный носитель | `Badge` = иконка + текст + цвет; статусы — деловые формулировки («Заказ ожидает передачи на склад») |
| Минимализм и спокойная палитра | Нейтральная палитра; брендовые цвета не придуманы — заменяются токенами `--primary*` после утверждения (UX-01) |
| Подтверждение только для необратимого и финансового | `ConfirmDialog` с итогом операции (сумма, получатель, последствия) — публикация начисления, распределение оплаты, отмена, отзыв доступа |
| Ошибка — у поля и понятным текстом | Сервер возвращает код (API-04), текст и поле (`hint`); `Field` показывает ошибку у поля; общая ошибка — `ActionError` с кодом запроса |
| Успех отражает фактический результат | Сообщения после команд говорят, что именно произошло («Заказ ЗК-… отправлен. Цены и количества проверены сервером»), а не «ОК» |

## 2 Токены

| Группа | Токены | Значение |
| --- | --- | --- |
| Поверхности | `--bg`, `--surface`, `--surface-2/3`, `--border`, `--border-strong` | Светлая и тёмная тема (`prefers-color-scheme`) |
| Текст | `--text`, `--text-2`, `--text-3`, `--link` | Контраст основного текста ≥ 7:1, вторичного ≥ 4.5:1 на поверхностях |
| Акцент | `--primary`, `--primary-hover`, `--primary-weak`, `--focus` | По брендбуку: чёрный #0F0F11 (светлая тема) / белый #FEFEFE (тёмная) |
| Бренд | `--brand-black` #0F0F11, `--metal` #C1C2C4, `--brand-white` #FEFEFE, `--metal-dark` | Шрифт Montserrat; логотип только белый или чёрный, без градиентов и искажений (`src/ui/brand.tsx`); паттерн «щит — крест — круг» в тёмных блоках |
| Смысловые | `--success/-weak`, `--warning/-weak`, `--danger/-weak`, `--info/-weak`, `--demo/-weak` | Всегда в паре с текстом и иконкой |
| Размеры | `--fs-xs…--fs-2xl`, `--space-1…6`, `--radius-*`, `--touch: 44px` | Сенсорная цель ≥ 44×44 (UX-08) |

## 4 Состояния экранов (UX-05)

| Состояние | Реализация |
| --- | --- |
| Загрузка | Скелет; модули грузятся по требованию |
| Первый запуск / нет данных | `EmptyState` с объяснением и следующим действием |
| Нет результатов | `NoResults` с запросом и предложением (в базе знаний — «Задать вопрос в поддержку» с подставленным запросом, KB-08) |
| Частичные данные | Карточки загружаются независимо; ошибка одной не скрывает остальные |
| Ошибка | Текст от сервера + код запроса (correlation ID) + «Повторить» |
| Нет прав / не найдено | Одинаковое поведение для чужого и несуществующего объекта (политика нераскрытия) |
| Офлайн | Баннер; обращения уходят в очередь устройства; финансовые операции — только онлайн |
| Устаревшие данные | Остаток на складе с временем обновления и источником; данные обновляются при возврате на вкладку |
| Несохранённый черновик | Автосохранение на устройстве (обращение, отчёт) и на сервере (корзина, статья); восстановление с уведомлением |
| Конфликт изменений | `version-conflict`: показ актуального состояния без потери ввода; в редакторе статьи — явный конфликт и загрузка актуальной версии |
| Успех | Сообщение о фактическом результате |

## 5 Адаптивность и доступность (UX-03, UX-08)

- Брейкпоинт 960 px: боковая навигация ↔ нижняя навигация; сетки в одну колонку.
- Проверено на 375 px: 12 основных экранов партнёра без горизонтальной прокрутки (автоматическая проверка в браузере).
- Клавиатура: ссылка «К содержимому», видимый фокус `:focus-visible`, перевод фокуса на основное содержимое при смене экрана, диалоги — нативный `<dialog>`.
- Экранные дикторы: подписи всех полей, `role="status"/"alert"` для сообщений, скрытые подписи иконок, `aria-current` в навигации.
- Масштаб 200%: вёрстка на flex/grid без фиксированных высот; основные действия переносятся, а не обрезаются.
- `prefers-reduced-motion` замедляет анимации.

Ограничение: проверка с экранным диктором и пользователями пяти ролей (UX-10) не проводилась — это шаг пилота.

## 6 Локализация (SUP-08)

Ключ перевода — русская строка; турецкий словарь — `src/platform/i18n.tr*.ts` (около 450 строк, требует вычитки носителем). Компоненты переводят свои строковые подписи автоматически. Содержимое (названия товаров, статьи базы знаний, договоры) — данные; переводные версии статей — следующий этап (см. specification.md, C-19).

## 7 Карта навигации и основные маршруты (UX-09)

```
Сегодня ─┬─ Моя работа ── Задача (взять → выполнить → проверка)
         ├─ Поддержка ── Новое обращение (+ инструкции по категории) ── Обращение (переписка, решение, подтверждение)
         ├─ Выручка (Моя смена · Отчёт точки)
         ├─ Магазин (категории, избранное, корзина) ── Заказ (строки, отгрузки, приёмка)
         ├─ Партнёры и точки ── Карточка партнёра
         ├─ Открытия ── Проект (блокеры, дорожная карта, перенос, разрешение)
         ├─ Роялти ── Отчёт (ввод/импорт → проверка → расчёт → начисление) ── Начисление ── Оплата
         ├─ База знаний ── Статья ── Редактор ── Согласование
         ├─ Обучение
         ├─ Обзор (исключения → списки)
         └─ Настройки (интеграции, очереди, доступ, аудит)
```

| Маршрут UX-09 | Путь в прототипе |
| --- | --- |
| Партнёр сдаёт отчёт | Сегодня → «Сдать отчёт» → период → выручка по точкам (или CSV) → «Отправить» (итог операции) |
| Партнёр заказывает | Сегодня → «Заказать» → каталог → корзина → «Оформить заказ» → заказ с деловым статусом |
| Менеджер ведёт открытие | Открытия → «Новый проект» → проект: блокеры → задачи шагов → «Выдать разрешение» |
| Специалист решает обращение | Сегодня/очередь → обращение → «Взять» → ответ → «Решить» со ссылкой на инструкцию |
| Сотрудник находит инструкцию | Поиск в шапке → результаты с выделением → статья → «Ознакомлен» |
| Финансы сверяют оплату | Сегодня → «Проверить сообщение об оплате» → «Сверить с выпиской» → другой финансист «Подтвердить» → начисление → «Распределить оплату» |
