## 2 Что не проверяется автоматически и почему

| Область | Причина | Как проверяем |
| --- | --- | --- |
| Истинная конкурентность (AT-10 с двумя соединениями) | PGlite — одно соединение | Последовательная проверка + `SELECT … FOR UPDATE` в коде; повторить на staging двумя параллельными сессиями |
| PostgREST, Storage API, Auth Supabase | Эмулируются локальным бэкендом разработки | Ручной чек-лист на демо-проекте (раздел 4) |
| pg_cron | Нет в PGlite | Проверка на проекте: «Настройки → Интеграции → Запуски обработки» показывает запуски «По расписанию» |
| Установка PWA, push, офлайн на iOS/Android | Нужны реальные устройства (PWA-02) | Раздел 4 |
| Доступность с экранным диктором, юзабилити | Нужны люди | UX-10 на пилоте |

## 3 Проверка в браузере (проведена 12.10.2026, локальный бэкенд разработки)

- Вход, выход с очисткой данных устройства, «Запомнить устройство».
- Партнёр (RU): «Сегодня», роялти с расчётом и формулой, отчёт за закрытый период.
- Финансы: «Сегодня» с согласованиями, утверждение отчёта со сменой ставки (разбивка базы 40 000 + 38 500 TRY → 5 302,50 TRY), блокировка самопубликации начисления.
- Партнёр (TR): интерфейс на турецком, обращение, каталог в TRY, мобильная вёрстка 375 px.
- Руководитель: 15 списков и детальные экраны заказов и открытий без ошибок и сообщений консоли; обзор исключений.
- 12 экранов партнёра на 375 px без горизонтальной прокрутки.

## 4 Приёмка прототипа (COST-12)

Выполняется после публикации на GitHub Pages с проектом Supabase. Два тестовых пользователя на разных устройствах.

| № | Проверка | Ожидание |
| --- | --- | --- |
| 1 | Открыть HTTPS-ссылку на компьютере и телефоне | Экран входа; плашка «Демонстрационный стенд» |
| 2 | Прямая ссылка на вложенный экран (`…/#/support/<id>`) и перезагрузка | Тот же экран после входа |
| 3 | Партнёр сдаёт отчёт; финансы проверяют | Отчёт виден финансам, сумма совпадает у обоих |
| 4 | Партнёр заказывает; финансы подтверждают оплату; оператор обрабатывает очередь | Заказ «передан на склад (демо)»; повторное нажатие не создаёт второй заказ |
| 5 | Менеджер ведёт открытие: задача партнёра с фото, блокеры, разрешение | Без обязательных шагов разрешение не выдаётся |
| 6 | Специалист решает обращение со ссылкой на инструкцию; партнёр подтверждает | Статус «закрыто», история полная |
| 7 | Сотрудник находит инструкцию с опечаткой в запросе | Статья найдена; партнёр не находит внутренние материалы |
| 8 | Финансы сверяют оплату: регистрация одним, подтверждение другим, распределение | Сальдо уменьшилось только после подтверждения |
| 9 | Изменения сохраняются после перезагрузки и повторного входа | Данные на месте на втором устройстве |
| 10 | Партнёр подставляет ID чужого объекта в адрес | «Не найдено» |
| 11 | Установка PWA (Android Chrome — «Установить», iOS Safari — «На экран Домой») | Приложение открывается без адресной строки |
| 12 | Новая сборка при открытом черновике обращения | Баннер «Доступна новая версия»; черновик сохранён после обновления |
| 13 | Выход | Черновики устройства удалены; кнопка «Назад» не показывает данные |
| 14 | Демо-маркировка | Все интеграции помечены «Демо»; статусы не выдаются за реальные |
| 15 | Резервная копия и восстановление | `npm run db:export`; восстановление в проект №2 по runbook; вход и сальдо совпадают |
| 16 | Таблица расходов | 0 ₽ по каждой позиции (delivery-plan.md) |
