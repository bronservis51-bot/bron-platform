# ADR-0002 Хостинг прототипа и разделение репозиториев

Статус: принято. Вариант репозитория выбран владельцем 12.10.2026: **один публичный репозиторий** (п. 3).

## Контекст
GitHub Free публикует Pages только из публичных репозиториев. Условия GitHub Pages: не для онлайн-бизнеса/коммерческого SaaS и не для чувствительных данных. Документы раздела 1 содержат внутренние сведения компании. Supabase Free: нет бэкапов, пауза после 7 дней неактивности.

## Решение
1. Прототип публикуется на GitHub Pages только с синтетическими данными; это демонстрация, а не production.
2. Рекомендуемая схема: приватный репозиторий `bron-platform` (код, документы, миграции) и публичный `bron-pwa-demo`, содержащий только собранную статику. Публикация — `npm run deploy` с компьютера владельца (скрипт собирает и пушит `dist` в ветку `gh-pages` публичного репозитория). Токены в CI не нужны.
3. **Выбрано:** один публичный репозиторий — код, документы (обезличены: без имён людей и условий договоров) и синтетический seed. Публикация — workflow `pages` (GitHub Actions) при каждом изменении `main`; ручной `npm run deploy` остаётся запасным путём. В репозиторий никогда не попадают реальные данные, внутренние документы и секреты (COST-20).
4. Supabase: проект №1 — демонстрация. Проект №2 Free — резерв/staging при необходимости. Платный тариф не подключается; карта не привязывается.

## Последствия
- Риск блокировки Pages при использовании как рабочей системы → постоянный хостинг выбирается после пилота (COST-14).
- Бэкапы — ручным экспортом (runbook backup-restore).
