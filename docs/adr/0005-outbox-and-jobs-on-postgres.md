# ADR-0005 Outbox, inbox и фоновые задания в PostgreSQL

Статус: принято

## Контекст
ARCH-04/05, INT-03/04: обмен через transactional outbox и inbox, at-least-once с дедупликацией, без удержания транзакции на сетевом вызове. COST-06: без постоянно включённого компьютера и без имитации таймером вкладки.

## Решение
- `outbox`: запись создаётся в транзакции команды; `dedupe_key` уникален.
- `app_private.process_outbox(limit)`: берёт записи `FOR UPDATE SKIP LOCKED`, вызывает адаптер по `topic`, переводит в `done`/`failed` (экспоненциальная задержка с джиттером)/`unknown`/`dead`.
- Для статуса `unknown` следующий запуск сначала выполняет сверку (поиск документа по внешнему коду), затем решает о повторе — AT-05.
- `inbox`: `unique(source, event_id)`; повтор события записывается как `duplicate` и не обрабатывается.
- Запуск: `pg_cron` каждые 5 минут, если модуль Cron доступен; команда `run_integration_jobs()` для оператора с `integration.operate` (кнопка в интерфейсе).
- Адаптеры прототипа — demo, работают внутри БД и эмулируют внешнюю систему таблицей `demo_external_doc`. Реальный адаптер — Edge Function, вызываемая через pg_net или worker (следующий этап); контракт `topic + payload → result` не меняется.

## Последствия
Нет exactly-once через внешние системы — только идемпотентные ключи и сверка.
