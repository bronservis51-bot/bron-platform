# Компрометация аккаунта

Владелец: владелец продукта · Исполнитель: `hr_admin`/`sysadmin` (access.manage) и администратор Supabase

**Ограничение ущерба (минуты):**
1. PWA: «Настройки → Доступ» → «Отключить» пользователя — все назначения отзываются, доступ к данным закрывается при следующем же запросе (проверка в БД, а не в токене), задачи возвращаются в очереди.
2. Supabase Dashboard → Authentication → Users → пользователь → Sign out / Ban — завершает сессии (действующий JWT живёт до 1 часа, но данных уже не получит).

**Восстановление:** новый пароль через консоль; повторное назначение ролей после проверки; при необходимости MFA (production, SEC-01).

**Сверка:** журнал аудита (`Настройки → Аудит`) за период: действия пользователя, затронутые объекты; финансовые операции — перепроверка вторым финансистом.

**Коммуникация:** владельцу и затронутым партнёрам — по согласованной политике (SEC-06).
